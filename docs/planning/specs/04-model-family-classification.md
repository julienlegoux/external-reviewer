# Question

Scope makes family exclusion the binary's job and is explicit that selection is by
*family*, never by provider, because `amazon-bedrock` serves Anthropic's models too
([decision](/scope/06-family-exclusion-rule.md)). The whole product rests on that
distinction.

**`kern-link` has no family field.** `ai.Model` carries `ID`, `Name`, `Api`, `Provider`,
`BaseURL`, cost, limits and compat — and nothing that says who *made* the model. The
grep is clean: "family" appears in the module once, in an unrelated comment in
`ai/retry.go`. So the concept that the product's central safety property depends on does
not exist in the dependency, and this project has to produce it.

The catalog data shows what there is to work with: `amazon-bedrock.json` carries ids
like `anthropic.claude-opus-4-5-20251101-v1:0` and `amazon.nova-2-lite-v1:0` — the
vendor is a prefix on the id. `google.json` and `google-vertex.json` carry bare
`gemini-3.1-pro-preview`, where the vendor is the provider. Aggregators (`openrouter`,
`vercel-ai-gateway`) use `vendor/model` ids and are fetched at runtime rather than
embedded, so their contents are not knowable at build time.

# Options

- **A classifier inside this binary: rules over `(Provider, ID)`, defaulting to
  "unknown".** Self-contained, testable offline against the embedded catalog, and free
  to be paranoid in a way a general-purpose library could not be.
- **Add a `Family` field to `kern-link`'s catalog.** The right long-term home, and it
  fights the thing `kern-link` *is*: a full-parity port whose catalog is generated by
  `tools/export-catalog` from a pinned upstream. A field upstream does not have becomes
  parity drift that every sync has to re-apply.
- **Declare the family per entry in the user's TOML.** Zero inference, and it moves a
  safety property into a hand-edited file where a typo silently sends Claude's work back
  to Claude. Exactly the failure the decision exists to prevent.

# Recommendation

**A classifier in this binary, over `(Provider, ID)`, that fails closed.**

Three rules, in order:

1. Provider is itself a vendor (`anthropic`, `google`, `google-vertex`, `openai`,
   `openai-codex`, `mistral`, `deepseek`, `xai`, `moonshotai`, `zai`, …) → that vendor
   is the family.
2. Provider is a reseller or aggregator (`amazon-bedrock`, `openrouter`,
   `vercel-ai-gateway`, `github-copilot`, `azure-openai-responses`, `groq`, `together`,
   `fireworks`, `nvidia`, `cloudflare-*`, …) → the family is parsed from the id's vendor
   segment: everything before the first `.` or `/`, after stripping a leading regional
   qualifier (`us.`, `eu.`, `apac.`, `global.`).
3. Neither rule produces a confident answer → family is **unknown**, and unknown is
   **treated as excluded**.

Rule 3 is the important one. The cost of a false exclusion is that a tier resolves to no
reviewer and the review runs natively — which scope already defines as a normal,
non-error outcome ([decision](/scope/06-family-exclusion-rule.md)). The cost of a false
*inclusion* is Claude reviewing Claude while reporting that it did not, which is the one
failure this product cannot detect after the fact. Those costs are not symmetric, so the
default is not either.

Matching is case-insensitive and substring-free — `anthropic.claude-…` matches on the
segment `anthropic`, never on "contains anthropic", so a model named
`not-anthropic-clone` is not silently reclassified.

The classification table is data in one file with a table-driven test over the whole
embedded catalog asserting that no `amazon-bedrock` id beginning `anthropic.` or
`*.anthropic.` ever resolves to a non-Anthropic family. That test is the executable form
of the concept's central warning.

# Verdict

Accepted at triage as recommended. The fail-closed default is the load-bearing half: a false exclusion costs a native review, a false inclusion costs Claude reviewing Claude while reporting otherwise. The catalog-wide table-driven test matters more given kern-link's upstream syncs refresh that catalog regularly — a new reseller id shape must fail the test rather than silently classify.

**Refreshed after [decision 05](/specs/05-tier-assignment-schema.md).** Two updates, no
reversal:

- **The escape hatch was considered and rejected.** An optional `family` key in the tier
  config, consulted only when inference returned unknown and unable to overrule a
  confident answer, was proposed to keep unusual providers usable. It was dropped: it is
  the only mechanism in the design that can weaken the fail-closed rule, and it exists on
  a user's disk where being wrong is silent. An unknown family is fixed by adding a line
  to this classifier's data table — in the binary, covered by the catalog-wide test.
- **The trap is now live rather than illustrative.** `openrouter` is one of the two
  providers in play, its ids are `vendor/model`, and it serves `anthropic/claude-*`. The
  reseller rule is what stops a tier assigned `anthropic/claude-opus-4-5` through
  OpenRouter from sending Claude's work back to Claude. Note also that `openrouter` is a
  *dynamic* provider: its models are absent from the embedded catalog until
  `Refresh` runs, so the classifier is tested against fixture data for that shape rather
  than against the embedded files alone.
